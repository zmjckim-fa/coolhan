## 4. 페이지별 명세
### 4.1 홈
- 배너 Swiper(루프) → 상품 탭 섹션 2개 → 후기 마퀴 → 푸터.
- 상품 행(가로형): 좌 이미지 130~140px 정사각 / 우 이름(굵게 14px) + 브랜드(13px #555) + 취소선 소비자가 + 판매가. `더보기` 버튼(`a.btnMore`)의 이동 대상은 확인하지 못함(목록 페이지의 더보기는 ajax `$M.displayMore`로 확인).
- 탭 전환은 클라이언트에서 미리 렌더된 여러 모듈 중 하나를 보이기(`displaynone` 토글), 탭 4개 `#one_collect`.

### 4.2 카테고리 목록
- 상단: 배너 이미지(카테고리 이벤트) → 빵부스러기(홈 > 카테고리) → H2 제목 → **정렬 select**(정렬방식 선택 / 신상품 `sort_method=5` / 상품명 `1` / 낮은가격 `3` / 높은가격 `4`) → "총 **405**개 상품이 있어요" + 보기 전환(2열 그리드 `grid2` / 1열 리스트).
- 카드: 썸네일(정사각 227px) → 이름 → 브랜드 → 취소선 소비자가 → 판매가 → **색상 칩**(`.chips`, 상품의 색 옵션 색상 원형 표시).
- 페이지네이션: **더보기(MORE n/N)** 방식, 한 번에 30개, 호출 `$M.displayMore(0,0,cate_no,30,...)`.
- 검색 조건: 정렬만 노출(필터 없음).

## 5. 핵심 기능: 상품 구성기 ("catalog viewer v2") — 커스텀 모듈
**성격**: 순수 **미리보기(이미지 교체)** 레이어. 구매 옵션은 카페24 네이티브 select가 담당("Purchase options remain Cafe24 native" 주석 확인). 구성기에서 색을 눌러도 장바구니 옵션이 자동 선택되지는 않는다(네이티브 → 구성기 방향 동기화만 있음).
- 마운트: `[data-catalog-viewer="v2"]` 요소를 `DOMContentLoaded` 후 0.5초 간격 20회 스캔(카페24 지연 로딩 대응).
- 데이터(`data-*` JSON): `assets`(키 → 이미지 URL), `colors`[{code,name,hex}], `bases`[[코드,이름,추가금]], `thumbnails`(색 → 썸네일), `dimensions`{base:[가로,높이,깊이], wheels:[…]}, `initial-color`, `title`.
- 이미지 키 규칙: `<색코드>-<view>`(view = official·front·left·right·top), `<색코드>-open`(문 열림), `<대표색>-<base>`(바퀴 구성), `<대표색>-glass_<base>`(유리패널). 즉 **색 14 × 시점 5 + 열림 + 바퀴/유리 변형을 사전 렌더(webp)**로 준비.
- UI 컨트롤: 시점 버튼(기준/정면/좌측/우측/상단), 문 열기 토글, 색상 스와치(14, `aria-pressed`), 바퀴 선택(기본 발 0원 / 고정형 4개 +111,000 / 고정 2+일반 2 +88,000 / 일반형 4개 +66,000), 상단 패널(기본/유리 +177,000), 박스 인서트(기본 구성/인서트 장착), 치수 표시(가로/높이/깊이 mm).
- 동기화: 네이티브 색상 select `change` → 구성기 색 변경 + 상세 상단 큰 이미지 `img.BigImage`/`.keyImg img` 썸네일 교체. `MutationObserver`로 카페24 지연 로딩이 `src`를 되돌리는 것을 방지.
- 구현 요구: **상품마다 사전 렌더 이미지 세트**가 필요(수백 구성 × 수십 컷). 구성 수가 많으면 자동 렌더링 파이프라인이 필수 — 가장 큰 제작 비용.

## 6. 옵션·가격 데이터 모델 (848개 전수에서 도출)
```
Product(상품)            : product_no, slug, 이름, 브랜드, 카테고리[], 소비자가=판매가, 배송기간 유형, 상태 태그[국내재고/입고예정/B급]
 └ ColorOption(필수 옵션) : item_code = <상품코드><옵션ID 4자리> (예 P0000FKG000D), option_value(색), option_price, stock flags
 └ AddonProduct(추가구성상품, 숨김 부품 상품 1개/구성)
     └ 옵션(1단) 26종: 스티커/바퀴/보강재/타공/열쇠핸들/선반/유리패널/박스인서트…
     └ 상세(2단, 1단 값에 종속) 272종: 폭·색·수량별, 라벨에 추가금 표기 "(+100,000원)"
 └ 별도 상품 "USM 이노스 5칸": 색 14, +325,000원
```
- 주문 행 구조: `option_product`(본 상품, 수량 입력) + `add_product`(부품, 수량·가격 별도) → 합계 = Σ(행 가격×수량). 예: 3,247,000 + 100,000 = 3,347,000, "(2개)".
- 정확한 가격 규칙: `판매가 = 소비자가`(할인 0%), **빠른배송(국내재고) = 일반배송 × 1.028**(378쌍 전부), 무통장 가입 회원 **4% 추가할인**(최적할인가), 쿠폰 3%(≥500만) / 5%(≥1,000만).
- 색상 이름 변형: 재고 없는 색은 `(5주 소요예정)` 접미 → **재고 상태를 옵션 이름에 넣는 방식**(우리는 별도 재고 필드 권장).

## 12. 2차 분석 결과 (2026-11-02) — 전수 DB화와 보강

상세 목표/기준은 `ANALYSIS_GOALS.md`, DB는 `DB_README.md`·`thereum_catalog.sqlite`(검증 15/15 PASS).

### 12.1 1차 설계서 정정
- **"판매가 = 소비자가"는 제작주문 상품에만 맞다.** 국내재고 443개는 판매가가 소비자가보다 낮다(평균 96%, 범위 84~97%). 최적할인가는 판매가의 약 4% 아래(0.91~0.96).
- **상품은 848개가 전부가 아니다.** 상품번호 1~4200 조회에서 **회원 전용 975개**가 더 있다("일반회원만 구매할 수 있어요", 로그인 필요). 이 975개는 내용을 보지 못했다. → 사용자가 직접 로그인한 브라우저 세션이 있어야 수집 가능.
- 부품 옵션 행 141,039개 중 **사이트에 표시·판매되는 것은 24,189개**. 나머지 116,850개는 숨김 템플릿 행(가격 0 또는 미사용). 화면에 보이는 옵션만 쇼핑몰 데이터로 써야 한다.
- 이노스 5칸은 1종이 아니라 2종(제작주문 325,000 / 국내재고 344,000). 부품 상품도 구성마다 따로 존재(상품 3646 → 부품 상품 3644, 상품 3647 → 3645).

### 12.2 T1 주문·결제 흐름 (정적 분석, 코드 위치 확인)
- 흐름: 상세 `product_submit` → `POST /exec/front/order/basket/` → `/order/orderform.html?basket_type=all_buy` → 결제예약 `POST /exec/front/order/reserve/`(`precreateOrder`) → 금액계산 `POST /exec/front/order/Calculationcreate/`.

- 주문서 화면 자체와 결제수단 목록은 장바구니가 비어 있고 주문 제출을 하지 않아 **확인하지 못했다**(사이트가 안내하는 결제는 무통장입금).
