# 실패 방지 대응표

> 쿨한 현장 교훈(`knowledge_base/field-lessons.json`) 중 이 프로젝트에 해당하는 것마다 한 행을 쓴다. 해당하지 않으면 방지책 칸에 «해당 없음: 이유»를 쓴다. 해당 교훈 목록은 `node scripts/coolhan.js field-lessons list --kind fail --tags @tags`로 뽑는다.

교훈 태그: ui

| 교훈 ID | 방지책 | 검증 방법 |
|---|---|---|
| F-01 | 구현 단위의 완료 증거는 실제 서버를 띄워 API를 부르고 DB에서 되읽은 시험 결과다. 화면 파일은 실제 경로(`/`, `/admin/...`)에서 응답으로 나와야 한다 | `node --test test/`의 통합 시험이 서버를 띄우고 저장 뒤 A-01로 되읽는다. 원장 완료 칸에 시험 수치를 적는다 |
| F-12 | 요구는 R-01부터 R-06 여섯 가지로 고정한다. 구현 단위마다 요구 번호를 적고 범위 밖 목록(`00_기획서.md` 1절)을 둔다 | `plan-check`가 단위마다 요구 번호를 확인한다. 라우트 표의 경로 수가 API 11개와 화면 4개와 같은지 시험이 센다 |
| F-13 | 백엔드 하나(`src/`의 Node 서버), 관리자 표면 하나(`/admin`), 저장소 하나(SQLite 파일)로 적었다. 바꾸려면 결정 로그에 새 행을 쓴다 | `05_소스.md` 폴더 구조와 결정 로그 D-02를 대조한다 |
| F-16 | 입력칸마다 저장 컬럼, 방문자 화면 위치, 관리자 화면 위치, API를 적은 필드 목적지 지도를 `03_화면.md`에 둔다. JSON 필드 이름은 컬럼 이름과 같다 | 관리자 API로 저장한 모든 필드를 A-01과 관리자 읽기 API로 되읽어 같은지 보는 시험 |
| F-20 | 외부로 나가는 것이 없다(메일, 문자, 결제, 유료 API 0개). 시험은 임시 DB 파일과 스스로 만든 환경 값으로만 돈다 | 시험 코드가 `DB_FILE`을 임시 폴더로 정하고 끝나면 지운다. 시험이 실제 `data/` 폴더를 건드리지 않는지 확인한다 |
| F-24 | 시험은 문구 글자가 아니라 문구 키와 오류 코드를 비교한다. 개수 기대값은 분류 목록과 라우트 표에서 계산한다 | 시험 코드에 화면 문구 문자열이 없는지 고정 검증의 단일 원천 검사가 본다 |
| F-25 | 분류 목록, 검증 규칙, 영업 상태 계산, 문구 사전, 라우트 표를 각각 한 파일에 둔다. 서버와 화면이 같이 쓰는 값은 서버가 API로 내려 준다 | 고정 검증 C4(단일 원천과 중복)와 문구 키 정적 검사 |
| F-27 | 구현 전에 화면 구성안(와이어프레임 SVG), 참조 체계(`kleinanzeigen-design-system`), 문구 사전, 글자 상한(메뉴 이름 40자)을 기획서에 둔다 | 기획 게이트가 도식 파일 존재를 확인한다. 브라우저에서 40자 이름과 375px 폭을 확인한다 |
| F-28 | 방문자 화면의 문구는 사전의 한국어만 쓰고 코드 값(open, sold_out)과 설정 키를 내보내지 않는다. 화면이 약속하는 것은 영업 상태, 영업시간, 메뉴뿐이다 | 방문자 화면의 글자에서 상태 코드와 환경 변수 이름을 찾는 시험 |
| F-32 | 운영자 입력이 필요한 시점 표를 `00_기획서.md` 5절에 두었다. 개발과 검증에는 운영자 입력이 필요 없다 | `docs/BLOCKED.md`에 실제로 쓰기 시작할 때 필요한 환경 변수 이름을 적는다 |
| F-33 | 환경 명세(Node 버전, DB, 운영체제, 포트, 환경 변수)를 `05_소스.md`에 둔다. 필수 환경 변수가 없으면 서버가 시작하지 않고 이름을 알린다 | 필수 값 없이 서버를 띄우면 0이 아닌 코드로 끝나고 이름이 나오는지 보는 시험 |
