## 1. 기능 개요 (Feature Overview)

### Purpose
사용자가 제품/서비스에 대한 피드백을 제출할 수 있고, 시스템이 이를 저장하고 조회할 수 있는 기본 피드백 수집 시스템입니다.

**User Story:**
- AS A user, I want to submit feedback about the product
- SO THAT the company can improve their services
- WHEN I call the feedback API

### Scope Statement

**MVP Level - 기본 기능만:**
```
✅ Include:
- User feedback submission (POST)
- Feedback list retrieval (GET - list)
- Feedback detail retrieval (GET - by ID)
- Basic input validation
- Error handling

❌ Exclude (STRICTLY):
- Admin dashboard
- Analytics dashboard
- Health check API
- Internationalization (i18n)
- WebSocket real-time updates
- Advanced filtering/search
- Batch processing
- Caching layers
- Monitoring system
- Logging system extensions
```

### Key Characteristics
- **Simple MVP**: 3 endpoints, 1 database table
- **Authentication**: User authentication required (except unspecified)
- **No external dependencies**: Minimal dependencies
- **Baseline validation**: Email, message format only

## 2. API Endpoints (3개만)

### 2.1 POST /api/feedback
**Description:** Submit a new feedback from user

**Request:**
```json
{
  "message": "string (required, 1-500 characters)",
  "rating": "integer (optional, 1-5 scale)",
  "type": "string (optional, enum: bug|feature|general)",
  "email": "string (optional, for anonymous feedback)"
}
```

**Response (201 Created):**
```json
{
  "id": "uuid-string",
  "user_id": "uuid-string or null (if anonymous)",
  "message": "string",
  "rating": "integer or null",
  "type": "string",
  "email": "string or null",
  "status": "new",
  "created_at": "2026-05-31T10:00:00Z",
  "updated_at": "2026-05-31T10:00:00Z"
}
```

**Error Responses:**
- 400 Bad Request: Invalid input (message empty, rating > 5, message > 500 chars)
- 401 Unauthorized: Missing authentication (if required)
- 500 Internal Server Error: Database error

**Validation Rules:**
- `message`: Required, 1-500 characters, no null/empty
- `rating`: Optional, must be 1-5 if provided
- `type`: Optional, must be one of: bug, feature, general
- `email`: Optional, must be valid email format if provided

---

### 2.2 GET /api/feedback
**Description:** List all feedback (for authenticated users)

**Query Parameters:**
```
- page: integer (default: 1, min: 1)
- limit: integer (default: 10, min: 1, max: 100)
- status: string (optional, enum: new|read|responded)
```

**Response (200 OK):**
```json
{
  "data": [
    {
      "id": "uuid-string",
      "user_id": "uuid-string or null",
      "message": "string (truncated to 100 chars)",
      "rating": "integer or null",
      "type": "string",
      "status": "new|read|responded",
      "created_at": "2026-05-31T10:00:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "pages": 5
  }
}
```

**Error Responses:**
- 401 Unauthorized: User not authenticated
- 500 Internal Server Error: Database error

**Business Rules:**
- Users see only their own feedback (user_id filter applied server-side)
- Pagination default: 10 per page
- Results sorted by created_at DESC (newest first)

---

### 2.3 GET /api/feedback/:id
**Description:** Get detailed feedback by ID

**Response (200 OK):**
```json
{
  "id": "uuid-string",
  "user_id": "uuid-string or null",
  "message": "string (full message)",
  "rating": "integer or null",
  "type": "string",
  "email": "string or null",
  "status": "new|read|responded",
  "created_at": "2026-05-31T10:00:00Z",
  "updated_at": "2026-05-31T10:00:00Z"
}
```

**Error Responses:**
- 401 Unauthorized: User not authenticated
- 404 Not Found: Feedback ID not found or belongs to different user
- 500 Internal Server Error: Database error

**Business Rules:**
- Users can only access their own feedback (authorization check)
- Returns full message text (not truncated)

## 3. Database Schema

### Table: feedback

```sql
CREATE TABLE feedback (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID,
  message TEXT NOT NULL,
  rating INT CHECK (rating >= 1 AND rating <= 5),
  type VARCHAR(50) DEFAULT 'general' CHECK (type IN ('bug', 'feature', 'general')),
  email VARCHAR(255),
  status VARCHAR(50) DEFAULT 'new' CHECK (status IN ('new', 'read', 'responded')),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  -- Constraints
  CONSTRAINT message_length CHECK (LENGTH(message) >= 1 AND LENGTH(message) <= 500),
  CONSTRAINT valid_email CHECK (email IS NULL OR email ~ '^[^@]+@[^@]+\.[^@]+$'),
  
  -- Foreign Key (references member_accounts or users table)
  CONSTRAINT fk_user_id FOREIGN KEY (user_id) REFERENCES members(id) ON DELETE SET NULL
);

-- Index for common queries
CREATE INDEX idx_feedback_user_id ON feedback(user_id);
CREATE INDEX idx_feedback_created_at ON feedback(created_at DESC);
CREATE INDEX idx_feedback_status ON feedback(status);
```

**Column Descriptions:**

| Column | Type | Nullable | Constraints | Notes |
|--------|------|----------|-------------|-------|
| id | UUID | NO | PK | Unique feedback identifier |
| user_id | UUID | YES | FK to members | NULL for anonymous feedback |
| message | TEXT | NO | 1-500 chars | Core feedback content |
| rating | INT | YES | 1-5 | Optional satisfaction rating |
| type | VARCHAR(50) | NO | bug/feature/general | Feedback category |
| email | VARCHAR(255) | YES | Valid email | Contact info for anonymous users |
| status | VARCHAR(50) | NO | new/read/responded | Tracking status |
| created_at | TIMESTAMP | NO | Default NOW() | Feedback submission time |
| updated_at | TIMESTAMP | NO | Default NOW() | Last modification time |

**Data Constraints:**
- Message length: 1-500 characters (checked in DB and API)
- Rating: 1-5 or NULL
- Type: Must be one of predefined values
- Email: Valid email format or NULL

## 5. Business Rules

### 5.1 Feedback Submission
1. Message is mandatory (cannot be empty)
2. Message length: 1-500 characters
3. Rating (if provided): Must be integer 1-5
4. Type: Must be one of: bug, feature, general
5. Email format validation (if provided)
6. New feedback starts with status = 'new'

### 5.2 Feedback Retrieval
1. Users can view only their own feedback (enforced by user_id)
2. Anonymous feedback (user_id = NULL) only accessible via email verification
3. Feedback list paginated (default 10, max 100 per page)
4. Results sorted by created_at DESC (newest first)
5. Status filter optional (new, read, responded)

### 5.3 Data Retention
- Feedback retained indefinitely (no auto-delete policy)
- Users cannot delete their own feedback (MVP doesn't include DELETE)
- Status updates only by admin (future enhancement)

### 5.4 Privacy
- Email addresses in feedback are not displayed in list view (only in GET by ID)
- user_id is not exposed to non-owner users
- Anonymous feedback (NULL user_id) protected from cross-user access

## 6. Security Requirements

### 6.1 Authentication
- **Required for:** POST /api/feedback, GET /api/feedback, GET /api/feedback/:id
- **Exception:** Anonymous feedback allows email-only submission (optional user_id)
- **Method:** JWT token in Authorization header or session cookie

### 6.2 Authorization
- **User ownership:** Users can only access their own feedback
- **Server-side enforcement:** Filter queries by user_id from JWT
- **Admin future-proof:** Table designed for admin-only endpoints (future enhancement)

### 6.3 Input Validation
- SQL injection prevention: Parameterized queries only
- XSS prevention: Sanitize message input (remove HTML tags, encode special characters)
- Email validation: Use regex for format check
- Message truncation: Enforce 500-char limit in DB constraint

### 6.4 Rate Limiting (Basic)
- Optional: Limit to 10 feedback submissions per user per hour
- Optional: Implement in API layer if needed

### 6.5 Data Protection
- Messages stored as plain text (encrypt at rest if PII detected in future)
- Emails encrypted at rest (recommended)
- No sensitive data in logs (error messages don't contain user messages)

## 7. Performance Requirements

### 7.1 Response Time SLA
- POST /api/feedback: < 500ms (p95)
- GET /api/feedback: < 1s (p95) for default 10 items
- GET /api/feedback/:id: < 200ms (p95)

### 7.2 Throughput
- Support 100 feedback submissions per second per instance
- Scalable to multiple instances via load balancer

### 7.3 Data Volume
- Initial: < 10,000 feedback records
- Growth rate: Assume 100-1000 records/day
- Index optimization at 100k+ records (future)

### 7.4 Concurrency
- Database: Support 20 concurrent connections
- API: Support 100 concurrent requests
- No unique constraint on message (allows duplicates)

## 8. Error Handling

### 8.1 HTTP Status Codes

| Status | Scenario | Response |
|--------|----------|----------|
| 200 | GET successful | Feedback data in response |
| 201 | POST successful | Newly created feedback with id |
| 400 | Invalid input | VALIDATION_ERROR with field details |
| 401 | Missing auth | UNAUTHORIZED with hint to authenticate |
| 403 | Access denied | FORBIDDEN (accessing other's feedback) |
| 404 | Resource not found | NOT_FOUND with feedback ID |
| 500 | Server error | SERVER_ERROR with error code |
| 503 | Service unavailable | Database down, retry-able |

### 8.2 Validation Error Details

**Example: Missing message**
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      {
        "field": "message",
        "rule": "required",
        "message": "Message is required"
      }
    ]
  }
}
```

**Example: Invalid rating**
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": [
      {
        "field": "rating",
        "rule": "range",
        "message": "Rating must be between 1 and 5"
      }
    ]
  }
}
```

### 8.3 Retry Strategy
- Idempotent POST: No (each POST creates new feedback)
- Retryable errors: 5xx, 503
- Non-retryable errors: 400, 401, 403, 404


```
❌ Analytics/reporting
❌ Feedback editing (no PUT/PATCH)
❌ Feedback deletion (no DELETE)
```

### 12.2 Technical Constraints

- Single database server (no multi-region)
- No sharding (assuming < 1M records)
- Retention: Infinite (no data cleanup policy)

**API:**
- No GraphQL (REST only)
- No pagination cursor (offset-based only)
- No sorting options (created_at DESC only)
- No aggregations (no COUNT endpoints)

**Authentication:**
- JWT or session-based (specific method TBD by developer)

- No API key (out of scope)
