# 최소 소스 · 단일 원천 · 진행 원장 개발 원칙 (Minimal Source / Single Source of Truth / Progress Ledger)

> **구동 문서 (driving doc).** 사용자가 2026-10-31 지정한 표준 개발 원칙. 모든 새 개발·리팩토링·자동화 작업에
> 기본 적용된다. 기계 검사 가능한 부분은 G20 게이트 3종이 집행하고(부록 A), 판단이 필요한 부분은 에이전트
> 체크리스트 + 사람 몫으로 남긴다. 원문 §0–§13은 사용자 지시를 실질 그대로 옮긴 것이다.
>
> **적용 범위:** 쿨한이 만드는 모든 프로젝트 + 쿨한 하네스 자신(새 코드부터, §4-d). 이 저장소의 자기 적용
> 현황은 `docs/SINGLE_SOURCE_MAP.md` · `docs/PROGRESS.md` · `docs/CHECKS.md`.

## §0 제0 규칙 — 최소 소스

파일에 소스가 가장 적게 들어가면서 기능이 구현되는 방법으로만 짠다. 새 기능 = ① 이미 있는 모듈·함수·설정·
레지스트리를 부르는 줄 ② 그래도 모자라는 최소 줄. 같은 기능을 두 번 쓰지 않는다. «적게»의 기준은 **중복 0**이지
한 줄 압축이 아니다 — 함수 하나는 일 하나, 읽어서 이해되는 코드만.

## §1 단일 원천 — «한 곳만 고치면 전체가 바뀐다»

값·규칙·문구·모양은 각각 한 곳에만 둔다. 어느 프로젝트든 최소 이 여덟 종류의 «한 곳»이 있어야 한다:

| ID | 한 곳 | 내용 |
|---|---|---|
| S1 | 디자인 토큰·공통 스타일 | 화면은 클래스 이름만 쓴다 |
| S2 | 문구 사전(언어별) | 코드·화면·오류·메일은 키로 부른다 |
| S3 | 외부 대상 레지스트리 | 마켓·채널·제공자 — 대상 하나 = 파일 하나: 능력·규격·요구값·예외 |
| S4 | 파생 표 | (기능 × 대상 × 자격 → 가능 여부·옵션·필요값)를 S3에서 **계산하는 함수** — 손으로 적은 표 금지 |
| S5 | 설정 카탈로그 | 키·종류·단위·검증 — 기본값 없음 |
| S6 | 자격 | 등급·기능 플래그·한도 |
| S7 | 메뉴·화면 지도 | 데이터로 |
| S8 | 공용 라이브러리 | HTTP·쿠키·서명/검증·해시·시간·DB 열기 |

없는 종류는 새로 만드는 것이 아니라 **흩어져 있는 것을 찾아서 한 곳으로 모으는 것**이다.

## §2 새 파일·폴더 검문 5문 — 하나라도 걸리면 만들지 않는다

1. 같은 역할의 파일이 있는가 → 거기에 더한다
2. 값·문구·모양을 새로 적는가 → S1~S8에 넣고 이름으로 부른다
3. 외부 대상 이름이 코드 리터럴로 나오는가 → S3·S4 경유만(어댑터·스펙 파일 예외)
4. 사람 언어 문장이 코드에 나오는가 → S2 키로(주석·시험 이름·결정 기록 예외)
5. 일회성인가 → 저장소 밖. 끝나면 지운다

## §3 예외는 if가 아니라 레지스트리의 칸으로

특정 대상만 다른 값·규칙은 S3의 칸에 적고 코드는 읽기만 한다. 칸이 없으면 칸을 만든다.

## §4 진행 중인 프로젝트에 적용하는 순서 (점진적, 기능은 멈추지 않는다)

- **a. 현황 실측** — 파일 수·최대 파일·중복 도우미·인라인 스타일·하드코딩 문구·흩어진 표를 **숫자로**
  (`node scripts/single-source-check.js <root> --measure`).
- **b. 단일 원천 지도** — S1~S8마다 지금 위치(없음/부분/됨)·목표 파일 — `docs/SINGLE_SOURCE_MAP.md` 한 장.
- **c. 게이트 먼저** — 바꾸기 전에 동작 불변 스냅샷(대표 응답·화면 바이트·라우트 목록·시험 전부) +
  `--write-baseline`으로 측정 기준선 커밋.
- **d. 새 코드부터 규칙 적용.** 기존 코드는 손대는 파일만 그때 옮긴다 (래칫: 기준선 대비 증가 금지).
- **e. 큰 이행** (공용 lib → 토큰·스타일 → 대상 레지스트리 → 거대 파일 분리 → 문구 사전 → 파생 표 → 메뉴
  데이터 → 린트)은 단위마다 c 통과가 조건. 폴더 이동은 마지막·선택.
- **f. 린트로 금지 목록을 기계가 막게 하고 회귀에 넣는다** (`docs/CHECKS.md`에 등록).

## §5 동작 불변 증명

합치거나 지운 뒤에는 c의 스냅샷과 비교하고 관련 시험을 실제로 돌려 PASS/FAIL 수치를 적는다. 못 돌린 것은
«확인 안 함»으로 적는다 (C10: 실행하지 않은 것은 통과가 아니다).

## §6 보고 — 단위마다 1회, 5줄 이내

상태(완료/진행 중) · 무엇을 했나 · 줄 수 전후 · 시험 수치 · 다음 단위. 작업 중 채팅 설명 금지
(CLAUDE.md 전역 출력 규칙 3·9와 같은 규칙).

## §7 안전

비밀값·키·개인정보를 파일·로그·보고·채팅에 쓰지 않는다. 외부 시스템(서버·결제·외부 API·메일)은 승인 전
접속하지 않는다. 이름·값·경로를 짐작하지 않는다 (C12 존재 확인).

## §8 기록

단위마다 커밋(메시지 끝에 세션이 명시한 Co-Authored-By 트레일러), 결정 기록 파일(`docs/DECISIONS.md`)에
«무엇을 왜» 한 줄.

## §9 진행 원장 — 대화가 아니라 파일이 진실이다 (`docs/PROGRESS.md` 한 장)

- **목표 한 줄** (바뀌면 사용자가 바꾼다 — 모델이 바꾸지 않는다)
- **작업 목록:** 번호 · 이름 · 상태(대기/진행 중/완료) · 완료 증거(시험 수치·커밋 해시) · 남은 항목 이름
- **현재 위치** (지금 어느 번호의 어느 단계인가)
- **가정 목록** (묻지 않고 고른 기본값 — 번호·이유)
- **결함 목록:** D-번호 · 발견한 검사 · 파일:줄 · 상태(열림/닫힘)

규칙: 세션 시작·«이어서»·«계속»은 원장을 읽는 것으로 시작한다. 완료로 표시된 번호는 파일 상태로 재확인만
하고 다시 만들지 않는다. 단위 하나를 시작하기 전에 목표 한 줄을 다시 읽고 «이 단위가 목표에 속하는가»를 한
줄로 적는다 — 속하지 않으면 하지 않고 원장에 «범위 밖»으로 적는다. 단위를 끝내면 그 자리에서 원장을 갱신한다
(나중에 한꺼번에 금지).

## §10 완료의 정의 — 단어는 둘뿐

- **«완료»** = 그 단위의 완료 체크(코드 작성 · 검문 5문 · 고정 검증 목록 전부 통과 · 동작 불변 증거 · 린트 0 ·
  커밋 · 원장 갱신)가 모두 ✓. 하나라도 남으면 **«진행 중(남은 항목 이름)»**.
- «완료»라고 쓰면서 «확인 안 됨·추가 작업 필요»를 붙이는 것은 금지 — 그것은 «진행 중»이다.
  «대부분 완료»·«사실상 완료» 금지.

## §11 검증은 고정 목록으로 — 매번 같은 것을 같은 방법으로

- 프로젝트의 검증 목록(`docs/CHECKS.md`)을 정하고 «검증»은 그 목록을 **전부 실행**하는 것이다
  (`node scripts/checks-run.js`). 즉흥 검토로 대체하지 않는다.
- 목록에 없던 결함을 찾으면 ① 결함을 원장 D-번호로 등록하고 ② 그 결함을 잡는 검사를 목록에 추가한다 — 다음
  검증부터 자동 포함. 같은 종류의 결함이 두 번 «새로» 발견되면 안 된다.
- 검증 결과는 **«통과 n · 실패 m(D-번호) · 확인 안 함 k(이유)»** 세 숫자로만 보고한다.

## §12 수정은 결함 번호로만 — 맘대로 고치지 않는다

- «수정하라»에 결함 번호·파일·증상이 없으면 먼저 «무엇을(D-번호 또는 증상)»을 묻는다. 짐작으로 고치지 않는다.
- 번호가 있으면 그 결함의 원인 파일·줄만 고친다. 고치는 김에 다른 것을 바꾸지 않는다(발견하면 새 D-번호로 등록만).
- 수정 뒤에는 그 결함을 잡는 검사 + 고정 검증 목록 전체를 다시 돌린다.

## §13 물어볼 것과 스스로 정할 것

- **묻는다(작업을 멈추고):** 사용자 눈에 보이는 동작·데이터·범위·돈·외부 시스템이 바뀌는 선택인데
  문서·원장·코드에서 답을 찾을 수 없을 때. 질문은 선택지 2~4개 + 각 결과 한 줄로.
- **스스로 정한다(멈추지 않고):** 그 외 — 가장 안전한(되돌릴 수 있는·아무것도 지우지 않는·기존 동작 그대로인)
  쪽을 고르고 원장 «가정 목록»에 번호·이유를 적는다.
- **금지:** 묻지 않고 범위를 넓히거나 줄이는 것, «더 낫다»는 이유로 요청하지 않은 변경을 하는 것, 질문 대신
  추측으로 진행하는 것, 진행 대신 «계속할까요?»로 멈추는 것.

> §13과 CLAUDE.md의 Auto-Pilot 4조건은 같은 방향이다: 4조건(비밀값·비용·운영 데이터 파괴·요구 충돌)은
> 반드시 묻는 최소 집합, §13 첫 줄은 그 위에 «사용자가 보는 동작·범위가 바뀌는데 문서에 답이 없을 때»를
> 더한다. 둘 다 아니면 묻지 않는다.

## 부록 B — 쿨한 자체의 적합성 (2026-10-31 실측)

- 하네스는 CLI 스크립트 + 마크다운 저장소다. S1·S6·S7은 해당 없음(화면·자격·메뉴 없음). S3·S4·S5는
  해당 없음(외부 대상·설정 카탈로그 없음 — `--targets` 미지정).
- **S8 공용 라이브러리:** 없었음 → `scripts/lib/`(md-table · cli) 신설. 기존 스크립트의 `get`/`parseFlags`/
  `readText` 중복(3쌍)은 기준선에 기록, 손대는 날 이행(§4-d).
- **S2 문구 사전:** 없었음 → `scripts/messages/index.js` 신설(G20 스크립트 3종이 사용). 기존 스크립트의 인라인
  문구는 기준선 수치로 고정, 증가 금지.
- 수치·결함 번호는 `docs/SINGLE_SOURCE_MAP.md`와 `docs/PROGRESS.md`에 있다.
