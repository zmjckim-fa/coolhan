# bakery-hours

> 동네 빵집의 영업시간과 메뉴를 보여 주고 관리자가 고치는 사이트

## 인수인계
@HANDOFF.md

## 상시 지시
운영자가 프로젝트마다 반복해서 내리던 명령을 처음부터 넣어 둔 것이다. 같은 명령을 다시 내리지 않는다. 원본은 쿨한 본체의 `knowledge_base/field-lessons.json`이고 `node scripts/new-project.js . --refresh`가 이 블록을 다시 만든다. 손으로 고치지 말고 프로젝트에만 해당하는 예외는 이 블록 밖에 적는다.

- **O-01 «이어서»·«계속»은 지시가 아니라 기본 동작**: «이어서», «계속», «남은 작업»이라는 지시를 기다리지 않는다. 백로그가 빌 때까지 한 단위씩 끝내고 곧바로 다음 단위로 간다. 세션이 바뀌면 `docs/PROGRESS.md`의 현재 위치에서 시작한다. 질문은 이 네 경우에만 한다: 필요한 비밀값이 어디에도 없을 때, 비용이 드는 일, 운영 데이터를 되돌릴 수 없게 지우는 일, 요구끼리 충돌할 때.
- **O-02 작업 중 침묵, 보고는 한 번 5줄**: 작업하는 동안 진행 설명을 쓰지 않는다. 끝나면 5줄 이내로 한 번만 보고한다: 한 일, 검증 수치(통과 · 실패 · 확인 안 함), 다음 일. 넘치는 내용은 파일에 쓰고 경로만 적는다.
- **O-03 «완료»는 실제 검증 뒤에만**: «완료»는 `docs/CHECKS.md` 전체를 실제로 실행해 에러와 미완성이 0건일 때만 말한다. 검증하지 못한 것은 «확인 안 함»으로 적고 완료에 붙이지 않는다. «대부분 완료», «사실상 완료»는 쓰지 않는다.
- **O-04 분석과 기획을 끝낸 뒤 구현**: 코드를 고치기 전에 분석을 끝내고 기획을 끝낸다. 마지막 메시지만 보고 움직이지 않고 `_workspace/_goal.md`, `docs/PROGRESS.md`, 기존 산출물을 먼저 읽는다. 질문에는 답만 하고 코드를 건드리지 않는다.
- **O-05 기획은 글이 아니라 산출물 네 가지**: 기획은 처음부터 네 가지를 각각 파일로 만든다: DB(실행되는 SQL, 인덱스, ERD, 시드를 실제로 돌려 검증), 화면 설계(목록, 화면별 명세, 와이어프레임, 흐름), 디자인(토큰, 컴포넌트, 색 대비 수치 검증), 소스(폴더 구조, API 계약, 타입, 시험 계획). 이름 규칙을 먼저 정해 네 산출물이 서로 맞게 한다. 기획서에는 `교훈 태그:` 한 줄과 실패 방지 대응표를 둔다.
- **O-06 모듈 저장소를 먼저 쓴다**: 새 기능을 만들기 전에 모듈 저장소(`coolhan.project.json`의 `modules`)를 읽기 전용으로 확인한다. 묶음마다 채택, 이식, 참조, 제외 중 하나와 근거를 `docs/plan/MODULE_PLAN.md`에 적는다. 한 기능은 사용자 화면, 관리자, API, 알림까지 한 세트로 기획한다. 저장소에 없는 것만 새로 만든다.
- **O-07 단위가 끝나면 묻지 않고 커밋**: 단위 하나가 검증을 통과하면 묻지 않고 바로 커밋한다. 경로를 지정해 스테이징하고 전체 추가, 남의 변경 되돌리기, stash는 쓰지 않는다. 같은 폴더의 다른 세션이 만든 변경은 건드리지 않는다. 원격 push는 이 규칙에 포함되지 않는다.
- **O-09 핸드오프는 스스로 갱신**: 단위가 끝나거나 세션을 마칠 때 `node scripts/coolhan.js handoff`로 `HANDOFF.md`의 현재 상태 블록을 갱신한다. 비밀값은 위치와 변수 이름만 적는다. 새 세션이 «HANDOFF.md 읽고 이어서 진행하라» 한 줄로 시작할 수 있어야 한다.
- **O-10 지어내지 않는다**: 값, 이름, 금액, 규칙, 도메인을 추측으로 정하지 않는다. 문서와 코드에서 찾고, 없으면 `[결정필요]`에 이유와 기본값을 적고 그 기본값으로 진행한다. 돈과 데이터 삭제는 기본값으로 진행하지 않고 사람에게 남긴다.
- **O-11 가짜 데이터와 껍데기 화면 금지**: mock 데이터, 하드코딩, 죽은 버튼, 껍데기 화면을 만들지 않는다. 사용자 화면과 관리자 화면은 같은 DB와 API를 쓴다. 데이터가 없으면 «없음»을 보인다. 외부 키가 없으면 가짜 외부 서버로 끝까지 돌리고 실호출 0건을 그대로 적는다.
- **O-12 화면에 설명 문장을 두지 않는다**: 화면에는 제목 밑 부제, 설명 문장, 같은 내용의 반복을 두지 않는다. 설명은 `?` 풍선 한 줄(10어절 이내)로만 둔다. 고객 화면에 내부 낱말, 설정 키, 코드 값을 쓰지 않는다.
- **O-13 디자인은 기본값이 아니라 선택**: AI 기본 스타일(알약 버튼, 글로우, 같은 카드 세 개 나열)을 쓰지 않는다. 기본 시각 체계는 운영자가 고른 `kleinanzeigen-design-system` 스킬이고 다르게 가려면 기획서에 사유를 적는다. 모바일 375px와 접근성 WCAG 2.2를 검증 목록에 넣는다.
- **O-14 금지 구역과 비밀값**: 다른 사이트, 다른 서버, 웹서버 설정, 컨테이너 구성, 비밀 키, 다른 서비스는 운영자 승인 없이 건드리지 않는다. 비밀값은 파일, 로그, 보고, 채팅 어디에도 쓰거나 복사하지 않는다. 위치와 변수 이름만 적는다.
- **O-15 검증이 운영을 건드리지 않게**: 검증 중에 실제 메일, 결제, 시험 주문을 운영에 만들지 않는다. 시험 데이터는 표시하고 지운다. 운영 데이터 변경은 스크립트를 준비하고 시험까지만 하고 적용은 사람이 한다.
- **O-16 키와 정보는 기능을 끝낸 뒤 한 번에**: 운영자에게 키, 계정, 정보를 요구하는 것은 모든 기능을 끝낸 뒤 한 번만, 꼭 필요한 것만 `docs/BLOCKED.md`에 모아 알린다. 그 전에는 가짜 외부 서버와 기본값으로 끝까지 진행한다.
- **O-17 병렬로 나누고 끝에 다시 검토**: 독립적인 조사, 기획, 구현은 영역별 에이전트로 나눠 병렬로 돌리고 하나 끝나기를 기다리며 멈추지 않는다. 끝나면 한 에이전트가 합친 결과를 다시 검토해 충돌과 빠진 것을 고친다.
- **O-18 정한 결정은 다시 묻지 않는다**: 운영자가 이미 정한 결정은 `docs/DECISIONS.md`와 `HANDOFF.md`에 적고 이어서 쓴다. 같은 것을 다시 묻지 않는다.
- **O-19 모듈은 가져다 쓰고, 고도화한 것은 저장소로 돌려준다**: 회원가입, 관리자, 결제 같은 기능을 새로 만들기 전에 `node scripts/coolhan.js modules list`에서 찾아 `modules add <이름>`으로 가져온다. 세션을 시작하면 `modules status`로 새 판을 보고 `modules update <이름>`으로 바꿔 끼운다. `coolhan_modules/` 안의 파일은 고치지 않는다. 프로젝트에서 더 좋게 만든 기능은 모듈 표준(쿨한 본체의 `knowledge_base/00_MODULE_STANDARD.md`: 이름 하나, 같은 하위 폴더, 파일 이름 규칙, 분리된 DB, 시험, 보안 문서)대로 정돈해 저장소에 새 모듈이나 새 판으로 올린다. 다른 프로젝트 폴더의 파일은 밖에서 바꾸지 않는다.

## 기준 파일
- 진행 원장 `docs/PROGRESS.md`: 진실은 대화가 아니라 이 파일이다. 세션을 시작하면 현재 위치부터 읽는다.
- 고정 검증 `docs/CHECKS.md`: «검증»은 이 목록 전체를 `node scripts/coolhan.js checks-run`으로 실행하는 것이다.
- 결정 기록 `docs/DECISIONS.md`, 운영자만 할 수 있는 일 `docs/BLOCKED.md`, 기획 산출물 `docs/plan/`.
- 설정 `coolhan.project.json`: 태그, 배포 허가(`deploy`), 모듈 저장소, 쿨한 본체 위치(`home`).
- 도구: `node scripts/coolhan.js <도구> …` (progress-check, checks-run, plan-doc-check, field-lessons, handoff, modules).
- 실패 방지: 내 역할의 교훈은 `node scripts/coolhan.js field-lessons list --owner <역할> --tags @tags`로 읽는다.

## 쿨한 본체
- 위치는 `node scripts/coolhan.js where`가 알려 준다 (`coolhan.project.json`의 `home`). 본체 폴더는 읽기만 한다.
- 진행 순서: 의도 분석, 화면 설계, 기획서, 기획 게이트, 구현, 검증, 시험, 배포. 세션의 스킬 목록에 `coolhan-development-orchestrator`가 있으면 그 스킬로 진행한다. 없으면 본체의 `.claude/skills/coolhan-development-orchestrator/SKILL.md`를 읽고 같은 순서로 진행하며 역할 정의는 본체의 `.claude/agents/`에서 읽는다.
- 기획서 표준은 본체의 `knowledge_base/00_PLANNING_DOC_STANDARD.md`, 실패와 성공 사례는 `knowledge_base/00_FIELD_LESSONS.md`다.
- 모듈 저장소(`coolhan.project.json`의 `modules`)는 읽기만 한다. 묶음 명세는 `_specs/`, 목록은 `node scripts/coolhan.js modules list`, 이 프로젝트의 결정은 `docs/plan/MODULE_PLAN.md`다.
