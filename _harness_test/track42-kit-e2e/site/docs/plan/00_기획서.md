# 00 기획서: 빵집 영업 안내

> 운영자 지시 원문: «동네 빵집의 영업시간과 메뉴를 보여 주는 사이트를 만들어라. 관리자가 메뉴와 영업시간을 고칠 수 있어야 한다.»
> 이름과 번호는 `01_공통규칙.md`가 정한다. 네 산출물은 `02_DB.md`, `03_화면.md`, `04_디자인.md`, `05_소스.md`다.

교훈 태그: ui

## 1. 제품

- 한 줄 정의: 방문자는 가게가 지금 열었는지, 요일별 영업시간, 메뉴를 한 화면에서 보고, 관리자 한 명이 로그인해 영업시간과 메뉴를 고친다.
- 목표 1: 방문자가 화면을 연 뒤 다른 곳을 누르지 않고 지금 영업 상태를 안다.
- 목표 2: 관리자가 고친 값이 저장되면 방문자 화면에 그 값이 그대로 나온다.
- 사용자 역할: 방문자, 관리자 (`01_공통규칙.md` 4절).

### 범위 밖(하지 않는 것)

- 주문, 예약, 결제, 장바구니.
- 회원가입, 고객 로그인, 관리자 여러 명, 권한 등급.
- 임시 휴무 공지, 공지사항, 이벤트, 후기, 문의, 사진 올리기.
- 메뉴 분류 관리(분류는 고정 네 가지).
- 메일, 문자, 푸시 알림.
- 여러 언어 전환(문구는 키 기반 사전에 두되 언어는 한국어 하나).
- 자정을 넘기는 영업시간.
- 서버 배포(배포 허가 값이 `none`이다).

### 성공 기준

- 방문자 화면(S-01)이 열리면 영업 상태, 일곱 요일의 영업시간, 분류별 메뉴가 한 번의 요청(A-01)으로 나온다. 확인: API 통합 시험과 브라우저 확인.
- 관리자가 영업시간을 저장하면(A-06) 바로 다음 A-01 응답의 영업시간과 영업 상태가 저장한 값과 같다. 확인: 저장 뒤 되읽는 시험.
- 관리자가 메뉴를 추가, 수정, 삭제, 품절 표시, 순서 변경하면 바로 다음 A-01 응답의 메뉴가 그와 같다. 확인: 저장 뒤 되읽는 시험.
- 로그인하지 않은 요청은 관리자 API 아홉 개(A-03부터 A-11) 모두에서 거절된다. 확인: 거절 시험 9건.
- 화면 문구는 모두 `web/text/ko.json`의 키로 나오고 소스에 한국어 문장이 0건이다. 확인: 고정 검증의 단일 원천 검사.
- 본문 글자와 바탕의 색 대비가 4.5 이상이고 375px 폭에서 가로 스크롤이 없다. 확인: 대비 계산 스크립트와 브라우저 확인.
- 자동 시험이 전부 통과하고 건너뛴 시험이 0건이다. 확인: `node --test "test/*.test.js"`.

## 4. 빠지기 쉬운 항목

### 4-1. 비즈니스(가격·결제·정산): 해당 없음: 파는 기능이 없다

메뉴의 가격은 보여 주기만 한다. 결제, 환불, 정산, 수수료가 없다.

### 4-2. 법무와 약관

| 항목 | 내용 |
|---|---|
| 개인정보 | 방문자의 개인정보를 받지 않는다. 쿠키는 관리자 세션 쿠키 하나이고 방문자에게는 쿠키를 심지 않는다 |
| 로그인 시도 기록 | `login_attempt.client_key`는 IP 주소를 해시한 값이다. 보존 기간은 `02_DB.md`가 정한다 |
| 약관 | 회원과 거래가 없어 이용약관이 없다 |
| 글꼴과 라이브러리 | 시스템 글꼴만 쓴다. 외부 라이브러리 0개 |
| 가격 표시 | [결정필요] 가격 표시에 부가세 포함 문구를 넣을지. 이유: 지시에 없고 가게마다 다르다. 기본값: 넣지 않고 입력한 금액만 보여 준다 |

### 4-3. 운영

| 항목 | 내용 |
|---|---|
| 지원 경로 | 해당 없음: 방문자 문의 기능이 범위 밖이다 |
| 백업과 복구 | SQLite 파일 하나를 복사한다. 절차는 `02_DB.md` |
| 복구 목표 | [결정필요] 복구 목표 시간과 복구 시점. 이유: 운영 환경이 정해지지 않았다. 기본값: 하루 한 번 파일 복사, 복구는 파일 되돌리기 |
| 장애 대응 | 서버가 필수 환경 변수 없이 시작하지 않고 빠진 이름을 알린다. 요청 오류는 코드와 함께 표준 오류 출력에 남긴다 |
| 모니터링 | 해당 없음: 배포 허가 값이 `none`이라 운영 환경이 없다 |

### 4-4. 품질 목표

| 항목 | 목표 | 확인 |
|---|---|---|
| 응답 | 메뉴 상한 개수에 이름 40자를 넣었을 때 A-01 응답 본문 64KB 이하 | [미검증] 상한 개수와 40자 이름에서의 본문 크기. 확인 방법: 통합 시험에서 상한까지 넣고 길이를 잰다 |
| 요청 본문 상한 | 16KB | 통합 시험의 거절 시험 |
| 브라우저 | 최신 Chrome, Edge, Safari, Firefox. 폭 375px부터 | 브라우저 확인(375px, 1280px) |
| 접근성 | WCAG 2.2 AA | 대비 계산 스크립트, 키보드 순서 확인, 라벨 확인 |
| 검색 노출 | 방문자 화면에 제목과 설명 메타. 관리자 화면은 색인 금지 | 응답 헤더와 메타 시험 |
| 가용성 | 해당 없음: 배포하지 않는다 | 해당 없음 |

### 4-5. 도메인 품질 관리

| 항목 | 규칙 |
|---|---|
| 영업시간 | 닫는 시각은 여는 시각보다 늦다. 5분 단위. 휴무인 요일은 시각이 없다 |
| 영업 상태 | 서버가 가게 시간대로 계산한다. 방문자 기기의 시간대를 쓰지 않는다 |
| 메뉴 | 이름 1자 이상 40자 이하, 가격 0원 이상 1,000,000원 이하 정수 |
| 품절 | 품절인 메뉴도 목록에 남고 «품절»이 글자로 보인다 |
| 저장 확인 | 저장 응답이 돌려준 값으로 화면을 다시 그린다. 화면이 서버에 없는 값을 들고 있지 않는다 |

### 4-6. 데이터와 분석: 해당 없음: 방문 기록을 모으지 않는다

방문자 추적, 분석 스크립트, 이벤트 수집이 없다.

### 4-7. 알림: 해당 없음: 요구에 알림이 없다

메일, 문자, 푸시 발송이 0건이다. 저장 결과는 화면의 저장 알림(C-14)으로만 알린다.

### 4-8. 테스트와 배포

| 항목 | 내용 |
|---|---|
| 시험 계층 | 단위(검증 규칙, 영업 상태 계산), API 통합(임시 DB 파일과 실제 서버), 문구 키 정적 검사, 브라우저 확인, 접근성 확인. 상세는 `05_소스.md` |
| 수락 기준 | 요구 R-01부터 R-06 각각에 통과한 시험이 하나 이상 묶여 있다. 거절 시험이 0건이면 통과가 아니다 |
| 실행 명령 | `node --test "test/*.test.js"` (고정 검증 C7) |
| 환경 | 개발 환경 하나. 검증은 임시 DB 파일에서만 돈다 |
| 배포와 롤백 | 해당 없음: 배포 허가 값이 `none`이다. 허가가 바뀌면 그때 배포 스크립트 하나를 기획한다 |
| DB 변경 절차 | `02_DB.md`의 마이그레이션 절 |

### 4-9. 위험 관리

| 위험 | 확률 | 영향 | 완화 |
|---|---|---|---|
| 관리자 비밀번호 추측 | 중 | 가격과 영업시간이 바뀐다 | 시도 횟수 제한, 긴 비밀번호 요구, 세션 만료. `05_소스.md` |
| 메뉴 이름에 스크립트 삽입 | 중 | 방문자 화면에서 스크립트가 실행된다 | 화면은 글자로만 넣는다(textContent), CSP로 인라인 스크립트 금지 |
| 가게 시간대와 서버 시간대가 다름 | 중 | 영업 상태가 틀리게 나온다 | 시간대를 환경 변수로 받고 계산을 한 함수에 둔다. 경계 시각 시험 |
| SQLite 파일 손상이나 삭제 | 낮음 | 영업시간과 메뉴가 사라진다 | 파일 복사 백업 절차 |
| `node:sqlite`의 버전 차이 | 낮음 | 다른 Node 버전에서 서버가 뜨지 않는다 | 환경 명세에 Node 24를 적고 시작할 때 버전을 확인한다 |
| 요청하지 않은 기능이 들어감 | 중 | 범위가 커지고 검증하지 않은 화면이 생긴다 | 구현 단위마다 요구 번호를 적는다. 범위 밖 목록과 대조 |

| D-12 | 메뉴 순서를 관리자가 바꾼다 | 목록에는 정해진 순서가 필요하고 가게가 앞에 둘 메뉴를 고른다 | 등록한 순서로 고정 | 기획(기본값, 운영자가 뺄 수 있다) | 2026-11-17 |
| D-09 | 배포하지 않는다 | `coolhan.project.json`의 `deploy`가 `none` | 운영 서버 배포 | 운영자(설정) | 2026-11-17 |

오픈 이슈는 이 문서와 다른 부에서 결정필요 표기를 단 줄이다. 모두 기본값으로 진행한다.

- [결정필요] D-10, D-11, D-12는 지시 문장에 글자로 없는 기능이다. 이유: 통합 검토가 요청하지 않은 기능일 수 있다고 지적했다(교훈 F-12). 기본값: 셋 다 포함하고, 운영자가 빼라고 하면 해당 컬럼, API, 단추를 지운다

### 4-11. 용어집

| 용어 | 뜻 | 코드 |
|---|---|---|
| 영업 상태 | 지금 가게가 열었는지를 나타내는 값 | open, closed, dayoff, unset |
| 휴무 | 그 요일에 문을 열지 않음 | dayoff |
| 영업시간 정보 없음 | 그 요일의 영업시간을 아직 입력하지 않음 | unset |
| 품절 | 오늘 그 메뉴를 팔 수 없음 | sold_out |
| 분류 | 메뉴를 묶는 고정 네 가지 | bread, cake, cookie, drink |
| 방문자 | 로그인하지 않고 화면을 보는 사람 | visitor |
| 관리자 | 비밀번호로 로그인해 고치는 사람 | admin |

문서 버전은 git 기록으로 관리한다.

### 4-12. 단계 계획

| 단계 | 포함 | 선행 조건 | 완료 기준 |
|---|---|---|---|
| MVP | R-01부터 R-06 전부 | 기획 게이트 통과 | 고정 검증 전부 통과, 자동 시험 통과, 브라우저 확인 |
| 출시 | 해당 없음: 배포 허가 값이 `none`이다 | 운영자가 배포를 허가하고 서버를 지정 | 해당 없음 |
| 확장 | 해당 없음: 운영자가 지시한 것이 없다 | 운영자의 새 지시 | 해당 없음 |

## 5. 운영자 입력이 필요한 시점 (교훈 F-32)

| 시점 | 필요한 것 | 없을 때 |
|---|---|---|
| 개발과 검증 | 없음 | 시험은 스스로 만든 값으로 돈다 |

| 배포 | 배포 허가와 서버 | 배포하지 않는다 |
