# 01 공통 규칙

> 네 산출물(DB, 화면, 디자인, 소스)이 같이 쓰는 이름과 번호다. 다른 문서는 여기 적힌 이름을 글자 그대로 쓴다.
> 운영자 지시 원문: «동네 빵집의 영업시간과 메뉴를 보여 주는 사이트를 만들어라. 관리자가 메뉴와 영업시간을 고칠 수 있어야 한다.»

## 1. 확정된 사실과 가정

| 구분 | 내용 | 근거 |
|---|---|---|
| [관찰] | 요구는 영업시간 보기, 메뉴 보기, 관리자의 영업시간 수정, 관리자의 메뉴 수정 네 가지다 | 운영자 지시 원문 |
| [관찰] | 배포 허가 값은 `none`이다 | `coolhan.project.json` |
| [실측] | 이 기기의 Node 24.15.0은 `node:sqlite`(SQLite 3.51.3)를 플래그 없이 실행한다 | 2026-11-17 `node -e` 실행 결과 |
| [추론] | «관리자가 고친다»는 관리자만 고칠 수 있어야 한다는 뜻이므로 로그인이 필요하다 | 누구나 고칠 수 있으면 방문자가 가격을 바꿀 수 있다 |
| [결정필요] | 화면 언어. 이유: 지시에 언어가 없다. 기본값: 한국어 하나, 문구는 키 기반 사전에 둔다 | `00_기획서.md` 결정 로그 |
| [결정필요] | 자정을 넘기는 영업. 이유: 지시에 없다. 기본값: 지원하지 않는다(닫는 시각은 여는 시각보다 늦어야 한다) | `00_기획서.md` 결정 로그 |
| [결정필요] | 메뉴 분류. 이유: 지시에 분류 관리가 없다. 기본값: 고정 네 가지(빵, 케이크, 쿠키, 음료) | `00_기획서.md` 결정 로그 |

| 대상 | 형식 | 최종 권위 문서 |

| 컴포넌트 | C-01 | `04_디자인.md` |

다른 부의 번호를 표에 쓸 때는 이름 열에 최종 권위 문서의 이름을 글자 그대로 적는다. 한 번호에 이름은 하나다.

## 3. 요구 목록

| ID | 이름 | 역할 | 출처 |
|---|---|---|---|
| R-01 | 지금 영업 상태 보기 | 방문자 | 지시 «영업시간을 보여 주는» |
| R-02 | 요일별 영업시간 보기 | 방문자 | 지시 «영업시간을 보여 주는» |
| R-03 | 메뉴 보기 | 방문자 | 지시 «메뉴를 보여 주는» |
| R-04 | 관리자 로그인과 로그아웃 | 관리자 | [추론] 관리자만 고칠 수 있어야 한다 |
| R-05 | 영업시간 수정 | 관리자 | 지시 «영업시간을 고칠 수 있어야» |
| R-06 | 메뉴 추가, 수정, 삭제, 품절 표시, 순서 변경 | 관리자 | 지시 «메뉴를 고칠 수 있어야» |

이 여섯 가지 밖의 화면, 메뉴, API는 만들지 않는다(교훈 F-12).

## 4. 역할

| 코드 | 이름 | 로그인 | 할 수 있는 일 |
|---|---|---|---|
| visitor | 방문자 | 없음 | R-01, R-02, R-03 |
| admin | 관리자 | 비밀번호 하나(계정 하나) | R-04, R-05, R-06 |

회원가입은 없다. 관리자 비밀번호는 환경 변수로 받는다.

## 5. 상태 값

| 대상 | 코드 | 화면 표시 | 저장 |
|---|---|---|---|
| 영업 상태 | open | 영업 중 | 저장하지 않는다. 요청 시각과 영업시간으로 계산한다 |
| 영업 상태 | closed | 영업 종료 | 저장하지 않는다. 요청 시각과 영업시간으로 계산한다 |
| 영업 상태 | dayoff | 휴무 | 저장하지 않는다. 요일의 휴무 값으로 계산한다 |
| 영업 상태 | unset | 영업시간 정보 없음 | 저장하지 않는다. 그 요일의 여는 시각이 비어 있으면 이 값이다 |
| 메뉴 판매 상태 | on_sale | 판매 중 | `menu_item.sale_status` |
| 메뉴 판매 상태 | sold_out | 품절 | `menu_item.sale_status` |

## 7. 테이블 이름

| ID | 이름 | 용도 |
|---|---|---|
| T-01 | business_hour | 요일별 여는 시각, 닫는 시각, 휴무 |
| T-02 | menu_item | 메뉴 이름, 가격, 분류, 판매 상태, 순서 |
| T-03 | admin_session | 관리자 로그인 세션 |
| T-04 | login_attempt | 로그인 시도 기록(횟수 제한) |

컬럼 이름은 아래로 고정한다. 타입, 제약, 인덱스의 최종 권위는 `02_DB.md`다. 이름은 소문자와 밑줄, 단수형이다.

| 테이블 | 컬럼 |
|---|---|
| business_hour | weekday, opens_at, closes_at, is_day_off, updated_at |
| menu_item | id, name, price_krw, category, sale_status, sort_order, created_at, updated_at |
| admin_session | token_hash, csrf_token, created_at, expires_at |
| login_attempt | id, client_key, attempted_at, succeeded |

처음 상태: `business_hour`는 일곱 행이 항상 있고 처음에는 시각이 비어 있다(영업 상태 unset). `menu_item`은 비어 있다. 지어낸 영업시간이나 메뉴를 넣지 않는다(상시 지시 O-11). 시험용 자료는 `test/` 안에만 둔다.

## 8-2. API

| ID | 이름 | 메서드와 경로 | 권한 |
|---|---|---|---|
| A-01 | 방문자 화면 자료 | GET `/api/public/overview` | 없음 |
| A-02 | 로그인 | POST `/api/admin/login` | 없음 |
| A-03 | 로그아웃 | POST `/api/admin/logout` | admin |
| A-04 | 세션 확인 | GET `/api/admin/session` | admin |
| A-05 | 영업시간 읽기 | GET `/api/admin/hours` | admin |
| A-06 | 영업시간 저장 | PUT `/api/admin/hours` | admin |

| A-08 | 메뉴 추가 | POST `/api/admin/menu` | admin |
| A-09 | 메뉴 수정 | PUT `/api/admin/menu/{id}` | admin |
| A-10 | 메뉴 삭제 | DELETE `/api/admin/menu/{id}` | admin |

요청과 응답의 필드, 오류 코드의 최종 권위는 `05_소스.md`다. JSON 필드 이름은 컬럼 이름과 같다. 오류 응답은 `{"error":{"code":"...","text_key":"..."}}`이고 `text_key`는 화면 문구 키다.

## 9. 값의 형식

| 값 | 형식 | 예 |
|---|---|---|
| 요일 | 정수 0(일요일)부터 6(토요일) | 1 |
| 시각 | 24시간 `HH:MM` 문자열, 5분 단위 | 07:30 |
| 가격 | 원 단위 정수, 0 이상 1,000,000 이하 | 3500 |
| 가격 표시 | 천 단위 쉼표와 «원» | 3,500원 |
| 시간대 | 가게 시간대 하나, 환경 변수 `SHOP_TIME_ZONE`, 기본값 `Asia/Seoul` | Asia/Seoul |
| 시각 기록 | UTC ISO 8601 문자열 | 2026-11-17T04:00:00.000Z |
| 메뉴 이름 | 1자 이상 40자 이하 | 소금빵 |

## 12. 문서 표기 규칙 (기획 게이트가 읽는다)

- 줄표 문자와 과장어를 쓰지 않는다. 표에 빈 칸을 두지 않는다. 해당이 없으면 «해당 없음»이라고 쓴다.
- `추후`, `나중에`, `TBD`, `미정`을 쓰지 않는다. 정하지 못한 것은 `[결정필요] 내용. 이유: 내용. 기본값: 내용` 한 줄로 쓴다.
- 확인하지 못한 것은 `[미검증] 내용. 확인 방법: 내용` 한 줄로 쓴다.
- 풍선말은 표의 `풍선말` 열에 쓰고 10어절 이내다.
- 도식은 `docs/plan/diagrams/`의 SVG 파일이고 문서에서 이미지 링크로 건다.
